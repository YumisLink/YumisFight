# 测试与提交规范

## 当前测试授权

用户最新已恢复鬼泣、阿修罗、狂战士和转职相关测试；本轮可执行JUnit、相关架构检查和独立世界实机。按[待测试清单](待测试清单.md)记录实际结果，未覆盖的整体项目检查仍保持待测，不得把历史通过记录当成当前验收。

## 临时内容永不上传

临时目录、构建缓存、运行日志、临时脚本、测试输出和截图禁止进入Git提交、推送及上传包。正式游戏资源不按png等扩展名误删。已跟踪临时产物见[解除跟踪清单](临时产物解除跟踪清单.md)，保留本地，不改写历史；本次没有操作暂存区。

## 必要测试审批

只有十分必要的测试源码、辅助脚本和样例资料可以申请保留。暂存前提供用途、必要性、文件清单及具体diff；提交前复核并取得对应批准。新增差异必须补审。审批绑定文件内容哈希，不能只凭文件名批准后续全部修改；辅助验证代码也属于审批范围。

Java测试方法最多80个，Python测试最多10个。原105个Java方法已做价值精简；保留WAL恢复、资产原子性、词条同步、属性乘区、技能时间与工业能量高风险覆盖。旧存档合并测试随用户舍弃旧数据的决定改为当前格式/拒绝旧格式项目，不能为维持旧测试恢复兼容代码。不能仅因长期通过而删存档和事务保护测试。扩容须用户批准。

## 实际提交检查

检查工具tools/check-submission.ps1支持Worktree（暂存候选）、Staged（实际暂存内容）、Range（待推送每个提交）及Package（实际上传目录）。检查暂存内容及逐提交历史中的临时文件、测试哈希审批、架构fetch范围和公告，不能只检查.gitignore。截图/报告即使在中间提交添加后删除，也不得进入待推送历史。

每个Git提交新增一份`playerread/更新/<本机代号>/<年月日时分秒>-<主题>.md`公告；玩法变化更新对应模块Wiki。电脑代号只取不提交的本机环境文档。只选本任务文件，不git add .；保留其他任务改动。没有提交/上传指令时不提交、推送、创建PR或上传附件。

本轮没有提交或上传授权；真正准备暂存/提交时，仍须展示需要审批的具体测试差异并按实际清单复核。
