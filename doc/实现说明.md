## 2026-10-27 魔能工业首版（规则版本1、协议5）

工业代码在 `src/main/java/cn/yumis/fight/industry`，客户端菜单/渲染在 `src/client/java/cn/yumis/fight/client/Industrial*` 和 `DimensionalScreen`。设计数值见《魔能工业体系设计草案》0.4。新增44个设备方块、11个资源/压缩方块和33个物品，保留旧装备 `magic_stone`；工业魔刹石用 `industrial_magic_stone`。

- `IndustrialContent` 注册设备、物品、冷却液、配方类型、方块实体、菜单和标准物品/流体能力。`DeviceKind` 描述五级加工/信标、三档功能水晶及独立能源类型。
- `IndustrialRecipe` 使用标准Ingredient、SizedFluidIngredient，支持ID或标签；ItemStackTemplate/FluidStackTemplate延迟到组件注册完成后构造结果，适配26.2数据包加载阶段。计数材料用最大流匹配，重叠标签不重复消费同一份原料。加工、燃料、菜单升级使用同一数据入口。
- `IndustrialRules` 独立版本1，从 `data/yumis_dungeon_and_fight/rules/industrial.json` 重载。配方在 `recipe/industrial`，本模组生成数据脚本是 `tools/industrial_resources.py`。修改数值优先数据包覆盖；已开工批次/燃料使用保存的快照。
- `MachineBlockEntity` 保存15个物品槽、两只默认20,000 mB罐、原料托管、结果、已付费、精确工作量、燃烧余时、余能和绑定。输入槽、产物槽、水晶/燃料槽由类型限制；`FilteredHandler` 在ResourceHandler交易中实施各面权限。普通拆除掉一个含TypedEntityData的机器物品，不另掉库存；信标不打包储能/连线。
- `EnergyMath` 使用long和必要的BigInteger中间值，需求比例分配且轮转整数余数。`ProcessingWork`/`Fraction` 保存精确有理工作量；熔炉总速度和多输入轮转共享整机能力，不把每份小数tick向上取整。总费用高于1,000点核心容量仍可部分供能，最终费用精确相等。
- `IndustrialWorld` 是主世界SavedData，统一管理各维度索引、持久连接图、已加载核心和每tick结算。先发能和需求，再分配并将剩余存入各核心；当期产能直接供给，最后计算溢出。余额归每个核心，卸载中继只保留拓扑，不贡献其容量/余额。结构变化、放置与区块事件更新索引和待验证集合，不扫描覆盖范围全部方块，不强加载区块。闭环按连通分量去重。
- 发电机每tick保存整数功率余数、流体余数及燃料时间；缺液暂停、满网继续。涡轮/温差/核能采用标准流体Ingredient/能力，RTG无冷却需求；冷却液桶只在容器间使用，不创建世界流体方块。
- 传送每次重新查询源/目标访问面能力，预检后以Transaction提交插入/提取；同一双箱、失效身份、未加载目标均拒绝。收获使用SnapshotJournal把作物重置和完整掉落纳入同一事务。功能操作的预留仅锁定核心现有容量内的余额，可撤销、失败零消费；不会生成另一份独立余额。

- `DimensionalMenu` 固定逻辑索引，服务端同样拒绝隐藏页点击；快捷存入搜索全部合法容量，禁止往暂存插入。升级可从玩家背包及正常储物逐档扣材料。`ChunkedStrings` 将大附件/连接图分段编码，同时可读旧单字符串，避免416格带装备词条时超过NBT UTF长度。重生与原有保存链统一恢复这些字段。
- 界面提供配方材料/时间/费用、通货实际概率、问号和具体暂停原因；锻炉/信标有分层图与缺失格。BER提交漂浮晶体和功能图标，客户端显示请求的连线、覆盖和缺失位置。贴图及Aseprite源稿见 `art/new/industry`。

| 通货 | 稀有度 | 直接掉落 | 效果或来源 |
|---|---|---:|---|
| 蜕变石 | 普通 | 是 | 普通升稀有，新增1条随机词条 |
| 增幅石 | 稀有 | 是 | 稀有升神器，新增1条随机词条 |
| 富豪石 | 神器 | 是 | 神器升传说，新增1条随机词条 |

| 崇高石 | 传说 | 是 | 传说装备新增1条，最多6条 |
| 神圣石 | 史诗 | 是 | 重掷所有合格随机词条数值，保留类型、数量和元素 |
| 混沌石 | 神器 | 是 | 删除1条可删除词条，再随机生成1条替换，总条数不变 |

| 套装石 | 传说 | 不掉落 | 由套装拆解取得，赋予或替换目标套装 |
| 词条拆解石 | 传说 | 不掉落 | 仅保留注册及未开放提示 |

| 神话升级石 | 神话 | 不掉落 | 整件神话分解获得；神话等级+5，最高80 |

普通敌人、精英、Boss的通货出现率均为独立5%，成功生成1枚；这一步不读玩家掉宝率。第二步先抽稀有度，第三步在选中稀有度的自然通货中等概率抽1种：

| 稀有度 | 档次基础权重 | 档内等概率候选 |
|---|---:|---|
| 普通 | 50 | 蜕变石 |
| 稀有 | 25 | 增幅石、打孔石 |
| 神器 | 15 | 富豪石、混沌石、升级石 |
| 传说 | 7 | 崇高石、套装拆解石 |
| 史诗 | 3 | 神圣石、破溃宝珠 |

令玩家掉宝率为`p`，稀有度序号`r`为普通0、稀有1、神器2、传说3、史诗4、神话5。`Rules.DROP_RATE_BASE=1000`由装备品质和通货档次加权共同使用：

```text
档次实际权重_r = 档次基础权重_r × (1 + max(0,p)/1000)^r
选中稀有度_r的概率 = 档次实际权重_r / 所有可掉落档次实际权重之和
同档具体通货的条件概率 = 选中稀有度_r的概率 / 该档可掉落通货种数
每次合格结算获得该通货的概率 = 5% × 同档具体通货的条件概率
```

档次基础权重总和100。例如掉宝率0时神器档15%，富豪石、混沌石和升级石各占通货的5%；史诗档3%，神圣石和破溃宝珠各占1.5%。每次结算获得混沌石、破溃宝珠分别为0.25%、0.075%。掉宝率1000时档次总权重264，两者在通货中的占比分别约7.58%、9.09%。增加同档候选不会提高该稀有度的整体概率。不允许直接掉落的物品不会因掉宝率进入池；通货档次概率在对数域归一，避免极大但有限的属性导致溢出。大世界仍只由实际终结者抽取一份公开掉落，地下城仍为每名合格参与者独立判定。

`Affix.locked`独立于`base/fixed`保存；旧装备缺少该字段时默认为false。可删除词条必须同时满足非基础、非固定、未锁定，宝石内词条不进入删除候选。混沌石仅替换其中1条并保留该位置，可洗回原类型，但不与保留随机条重复；正常生成和崇高石同样去重。部位资格、百分比资格及武器随机元素附伤最多2条的限制继续生效。史诗、神话固定装备无法使用混沌石。

破溃宝珠每次只选1条尚未锁定的可删除词条，可连续使用至全部锁定；没有候选时不消耗。锁定只保护词条不被删除或替换，神圣石仍可重掷数值。两种新通货共用现有装备实例、revision、完整光标快照和WAL事务；成功扣1枚，失败回滚，重复请求返回相同结果。

## 2026-10-27 受击与字体更新

该轮首次使用协议3，现已由下述类型与命中结果改造升级至协议4，规则版本仍为6。NativeHits在Incoming仅拒绝真正无效命中，在LivingDamageEvent.Pre清零原生扣血，保留hurtServer局部成功结果及原版动画、声音、方向击退、盾牌和箭/三叉戟生命周期。客户端继续计算RPG份额；服务器签发的nativeRoot绑定会话、双方生命代次、basis、维度和实例，与receipt在同一WAL事务消费。重复operation只返回既有回执；换operation复用root拒绝。原生回执不重复播放受伤或击退，致死投影也抑制第二次受击表现。

NativeDamageMixin只在受管且非bridge的hurtServer首次读取invulnerableTime时返回0，Incoming同时将后续冷却置0，维持每碰撞结算。未受管实体和真正免疫保留原生规则。原版盾牌比例进入客户端，防御/抗性仍仅由既有公式计算一次。哥布林石弹使用窄范围Snowball参数适配，以正占位进入同一桥；原生实际生命不消耗占位值。非原生技能报告使用26.2的broadcastDamageEvent，Boss反馈带来源实体；技能多段和DOT仍走原报告节奏。

投射物通知携带DamageSource.getWeaponItem()保存的完整来源物品，EquipmentStats/NativeRules增加显式武器参数，避免三叉戟离手或射后换主手导致错算。角色等级、防具、属性来源及增益按命中时读取。

ModText提供稳定yumis_dungeon_and_fight:ui字体ID，供服务端组件及原版控件使用。UiFonts将它映射至用户选择，统一测宽、换行和绘制。默认组合Inter Frozen Medium→Source Han Sans CN Medium→Minecraft缺字回退，官方OTF原件和OFL保留在字体资源目录；沿用FreeType路径。伤害数字移除额外伪粗体。旧noto配置迁移为modern，旧资源ID保留兼容别名；导入字体、失败回滚和个人选择保留，遗留ui_imported定义改为稳定别名，防止丢失旧文件污染资源重载。

## 数据定义与稳定 ID

`data/yumis_dungeon_and_fight/rules/catalog.json` 定义区域覆盖、材料名称与图标、副本入口、属性显示名。材料由同一个注册物品 `crafting_material` 承载，内部数据保存定义 ID；同名材料共用 ID，可堆叠 64。改名不影响配方绑定。

`rules/equipment.json` 定义词条、基础属性曲线、部位模板、配方和套装。装备中的 `Gear` 有独立 UUID、版本和修订号，保存等级、品质、部位、外观、词条、孔位、套装和宝石。属性汇总时基础词条与随机、特殊、附魔和宝石词条使用同一路径；套装定义在达成件数后应用对应效果。神器升级石重建基础与已知数值型随机条基准并保持品质系数；旧史诗/神话升级石只替换基础词条。其余保存内容不重新抽取。

材料需求首先由等级映射到唯一产区，再按部位取装备或护甲材料。原版材料系数 `q=ceil(L/10)`；区域数量为固定值。定义加载时检查 1～80 级区域完整覆盖及材料引用，避免静默回退到错误材料。服务端重载并向客户端同步实际定义。

`data/<namespace>/equipment/slot_groups/*.json` 定义本模组的槽位组，`equipment/equipment/*.json` 定义物品/标签接受规则与属性。六个实际槽位由 `data/yumis_dungeon_and_fight/curios/slots/ydnf_*.json` 注册给 Curios，物品标签位于 `data/curios/tags/item/ydnf_*.json`。`ExtraInventory` 只作为事务和次元背包视图，装备实物由 Curios 持有；旧状态首次登录时迁入 Curios。管理员增减槽位通过 Curios 永久槽位修饰符实现，移除时先将装备存入等待领取记录，可用 `/ydnf equipment claim` 取回。第三方新增槽组还需提供对应的 Curios 槽位及标签。

## 成长、技能与来源接口

角色上限 80，原成长与经验曲线保留，51～80 级每级 2 自由点、65 SP。学习等级有硬上限；装备加级仅作用于已经学习且符合职业要求的技能，并进入被动、MP 与伤害计算。

`AttributeSources` 为每个玩家维护命名来源和修订号；重复替换、冲突内容和移除墓碑有明确处理。`CommonServices.attributes(UUID)` 提供内置来源注册表。属性使用命名空间 ID，通用 `applyNamed` 可处理外部属性；内置属性提供枚举构造器。`ITEM` 阶段作用于装备汇总，随后加入角色基础，再执行 `CHARACTER` 阶段和精神派生属性。每阶段按基础比例、加法、总量比例汇总。

`SkillParameters.register(id, provider)` 可注册参数来源，`remove(id)` 移除。每次起手调用 `forCast`，产生不可变 `Snapshot`，保存技能等级和以下参数：

| 参数 | 含义 |
|---|---|
| `slashes` | 斩击/分段次数，至少 1，取整数 |
| `damage` | 分段伤害倍率 |
| `finisher` | 终结伤害倍率 |
| `range` | 范围 |
| `duration` | 持续时间 |
| `interval` | 分段间隔 |

`Change` 按技能、参数与来源分别指定加法及倍率；同来源同参数不能重复。装备可保存参数类词条，后续无需改写施法主流程即可投放。起手后换装不会改变当前施法快照。

四个副职业经验使用大整数累计，阈值 `100L+25L(L-1)/2`，等级封顶 10，经验继续累计。普通制作、成熟作物收获、钓获奖励与等额职业币一起提交。成熟甜浆果右键收获和普通作物破坏收获分别接入对应实际完成位置。附魔状态和公共接口保留，正式附魔玩法延期。

## 共享生命与网络

`request`、`snapshot`、`state` 三个 JSON 载荷通道使用 26.2 NeoForge 双向处理器注册。握手包含协议与规则版本，客户端在主线程处理状态；服务端任务进入主线程队列串行执行。

客户端计算命中、伤害、MP、CD 和本机预测，服务端提交共享生命比例 `q`。报告包括会话、操作号、施加者生命代次、目标生命代次、扩血基准、维度及实例。服务端验证生命周期、实例成员、PVP 和有限数值，不增加距离或伤害上限校验。重复操作恢复原回执；同操作号换内容判冲突。提交持久化结果后广播生命与实际结算值。

死亡在同一批次中锁定唯一 `death/目标/生命代次`。实际扣血最多为剩余比例，因此并发致死不会分别发奖。来源会话、生命代次、维度或扩血基准失效时，持续异常和旧请求失效。

公开副本人数采用累计名单。新增参与者时按人数血量倍率扩血，保持绝对已损生命量；基准与修订号递增，旧伤害和异常不能沿用。离场后重新进入不会重复增加累计人数。跨维度客户端清除旧维度缓存，同时保留已经收到的新维度上下文。

## 背包事务与保存

`InventoryTransactions` 捕获原版背包、额外装备、54 格次元背包、光标、合成格、扩槽及原版操作号。一次操作先暂存修改并计算结果，恢复操作前快照，再将完整结果、去重回执和关联奖励以同一 WAL 批次落盘；随后重放到原版数据、保存并回读确认附件，最后写已应用标记。重连优先恢复未应用结果。

制作、通货、升级、套装提取、镶嵌、整件分解、私人奖励拾取及次元背包使用这条路径。容量不足或条件失败恢复前快照。容量处理独立于原版 `Inventory.add`，避免创造模式吞掉溢出物品。关闭菜单的光标和合成格优先放回背包、次元背包，最后进入持久化等待领取。

WAL 每条记录有长度与 CRC；完整记录提交后 `force(true)`，再更新内存。中断尾记录被截断，完整记录内容损坏则中止加载，避免把损坏状态当作新角色。检查点通过临时完整日志及原子替换完成。

此设计覆盖模组内事务。外部模组直接改写玩家数据、跨存储硬件故障及原版漏斗的断电时序不是已证明的全局原子事务；具体实测范围见验证记录。

## 副本与原版适配

两个副本使用独立维度内的固定区域。哥布林营地为三片区域，每区两波，最后落雷凯诺；龙人之塔为三层战斗波次及顶层鲁卡斯。门在对应两波完成后开放。活动区域保持区块加载；波次仅依据已死亡状态推进，不把加载中的实体当作死亡。关闭场次释放区块，旧场次实体加载时被清理。

营地迁移了 YDNF 的森林、帐篷、哨塔、祭坛及四片区域布局；塔楼迁移了四个实际楼层、12 格层高、交替楼梯及门窗装饰。投石哥布林、翼龙、Boss 使用独立战斗逻辑和预警；龙人等普通近战使用原版导航。雷笼由可见铁栏模型、碰撞实体与根定组成，三次不同攻击可破坏。鲁卡斯低血量分身有独立生命、伤害修正且不产奖励，主身死亡清理分身。

原版生命作为共享比例的投影。末影龙连接水晶治疗、凋灵出生/常态/击杀恢复转换为固定共享比例。原版武器、环境、护甲、抗性等进入客户端适配；原版自然回血不会绕过共享生命。完整多模组兼容及所有原版 Boss 阶段仍需专门游玩覆盖。

## 2026-10-28 属性、法师之血、金币
