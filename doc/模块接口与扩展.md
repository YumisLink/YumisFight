# 模块接口与扩展

2026年10月30日本批新增公开合同：角色基础归属、任务完成标记/觉醒、`InitialEquipment`与券使用动作端口；技能的`baseJob/available/weaponAllowed`、赫尔德实体/继承公式与现有战斗参与端口；`CurrencyRules`账户点券及通货升级资格；`DeviceType.slots/MachineSlots`设备布局。角色UI跨模块入口位于character/api/client，其他模块不直接调用其client实现。详细数据流、命令、资源与验证边界见[职业魔法师与通货升级器实现](职业魔法师与通货升级器实现.md)。未修改受保护底层。

入口统一在`src/main/java/cn/yumis/fight/modules`和`src/client/java/cn/yumis/fight/modules`。API是跨模块唯一入口；业务实现和平台适配留在模块内部。以下均不需要修改受保护架构。

装备、词条、材料、副本和工业当前仍可共用既有数据包资源文件的不同节，但解析、模型及生命周期各自拥有。改资源内容不必改底层调度器。若普通需求需要越过API或扩大统一算式/网络/事务能力，先解释缺口并按架构保护规则处理。

JSON编解码由模块自己拥有；装备的EquipmentJson保存嵌套词条扩展字段。ApplicationJson仅用于启动装配的组合包，不作为模块反向调用入口。模块可变实例只能在自己的用例或同一事务内改动，规则快照调用者只读。

## 技能权值与伤害分析接口

技能内容使用 `SkillBalanceProfile` 登记权值及参考命中时间，职业内容使用 `SkillBalanceStyle` 登记职业倍率、普攻与固有伤害。`SkillDefinition.damageParameter` 标记自有伤害通道，`SkillParameters` 解析后冻结在起手快照；装备固定附伤不乘全局基数。技能规则接入原整包发布与同步，不扩展受保护底层。装备授予绑定通过 `SkillLearning.canBind` 和角色模块 `SkillProgression` 端口传递当前属性。

战斗模块 `DamageAnalysis` 只持有本地统计轮次与来源凭据，`CombatPrediction` 消费实际伤害回执；训练通过独立入口送入。分析面板通过现有页面登记，角色页负责导航。完整合同及本任务待测试项见[技能权值与伤害分析](技能权值与伤害分析.md)，具体已批准系数见[倍率审阅表](技能权值倍率审阅.md)。

## 2026-10-29 页面、退级、入场与时钟接口

- `PlayerPageSurface`增加导航声明、右键区域与矩形图集绘制。页面拥有分类和回调；菜单壳安排侧栏与窄屏导航。搜索输入重建时保留焦点和光标。
- `JobTransitions.reduceSkill`返回既有`Change`，技能等级、SP、资源清理和操作回执参加同一WAL。`SkillReductions`按稳定ID登记定向处理；`CareerState.reductions`同步修订号，客户端幂等清理，服务端`reconcile`阻止旧Runtime恢复被清BUFF，新的有效起手解除该标记。冷却、其他技能及已发出攻击不清空。
- dungeons新增对character公开API的声明；`DungeonPorts.Players.progress`提供角色进度窄端口。`Progress.dungeonSync`保存偏好，`Dungeon.synchronization/syncFor`保存本场各参与者选择。入场写入偏好、参与资格和回执；战斗、HUD、奖励和统计统一读取本人选择。公开匹配键只有地图和难度；动态cell避开目录固定区及全部未关闭场次。
- `CombatSettings`由战斗模块解析，服务端TOML的`combatTimeoutSeconds`默认5，通过现有profile下发。`CombatTiming`和伤害榜事件显式接收时长；重载保留已有期限和区间。伤害分析凭据记录事件发生时间，暂停只影响计时，不丢迟到的有效回执。
- `IndustrialOpening`由世界工业服务持有，每玩家只保留最新预载请求。完整信息及51槽快照按16000字符分段校验，客户端就绪后复核令牌、原菜单、机器、距离及规则，再用小令牌开菜单。超时10秒只提示。正常进度变化不让预载失效；规则和升级变化重新预取。工业二级概率页读取同快照的概率。
- 队伍来邀由现有profile同步，接受/拒绝按稳定队伍ID校验；弹窗等待脱战、没有容器操作或施法的安全时机。删除申请字段与请求分支。

本批没有修改受保护底层，没有保留旧签名包装或旧存档转换。

装备制作器继续使用既有定义同步和原版容器内容包。`FabricatorMenu.initialContentsReady`在初始内容到达后置位；客户端模块延后显示制作器，等待角色/材料定义和初始槽位齐备，10秒超时关闭并提示。此门控不增加服务端装备效果或底层传输分支。

战斗确认附带本事件实际采用的combatDelayMillis，客户端分析以该值形成区间；避免重载期间已提交但尚未确认的命中使用不同脱战时长。

## 2026-10-30 计时沙袋与伤害榜

- `CombatTarget.networkTraining`区分服务器确认的计时训练目标和原有本地训练目标；`CombatPorts.Training`接收目标校验及回执事务中的统计记录。技能端口可提供服务器签发的命中时间，原生命中仍使用原有凭据时间。
- dungeons拥有计时会话、临时目标及`TrainingActions`窄入口；客户端在使用物品时捕获Alt状态，通过现有消息直接发起20秒或60秒请求，服务端复核会话、维度、物品、权限和位置。攻击者仅可命中自己的计时沙袋，召唤物沿用自身伤害来源规则。有效伤害与正常命中效果参加同一WAL批次，重复回执沿用既有幂等规则。结束后暂留不可见目标以验证时段内迟到回执，至结果期限结束清理；重启清除未完成的临时会话。
- `Target.healthProjection`与敌人生命成长使用同一倍率；副本伤害累计仍保存目标原等级对应的基准值，发送时以观看者当前等级与本场同步选择投影，排名、占比、条形及DPS均使用该投影。训练与副本复用同一HUD绘制，不修改统一属性算式或受保护网络层。
