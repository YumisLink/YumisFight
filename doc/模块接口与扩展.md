# 模块接口与扩展

入口统一在`src/main/java/cn/yumis/fight/modules`和`src/client/java/cn/yumis/fight/modules`。API是跨模块唯一入口；业务实现和平台适配留在模块内部。以下均不需要修改受保护架构。

| 需求 | 所属位置 | 修改步骤与约束 |
|---|---|---|
| 新增词条定义 | affixes/api/AffixDefinitions、AffixDefinition；equipment.json的affixes节 | 使用未占用ID，提供名称、运算、资格组、范围及效果revision；发布前验证整包 |
| 新词条运算或抽样方式 | affixes/api/AffixEffects、AffixGeneration、MagicEffects | 注册效果和加权生成组；装备仅提供资格与等级曲线，不识别具体词条ID；新分位语义在词条解析中说明 |
| 装备模板/加工 | equipment/api/EquipmentTemplates、EquipmentRules、EquipmentGrowth；application/EquipmentApplication | 生成捕获基础成长快照及词条来源；改物品必须走库存事务；更新装备档案，未设计版本不开放 |
| 属性来源 | attributes/api/AttributeSources、AttributeServices | 用命名空间及来源revision注册；装备接入由equipment/api/EquipmentAttributes、EquipmentStats完成 |
| 战斗结算参与者 | combat/api/CombatPorts；application/CombatApplication | 实现一个窄端口，由bootstrap注入；奖励必须参加同一事务，不能改为提交前通知 |
| 目标受击规则 | combat/api/CombatTarget.receive；dungeons/api/Target | 默认沿用LifeRules，训练目标在所属内容中返回满生命、完整伤害、无死亡ID的回执；继续使用同一伤害WAL事务，不新增中央目标类型分支 |
| 客户端预测 | combat/api/client/CombatPrediction | 状态端口只提供连接、生命、资源、目标定位和回执发送；待确认伤害、重发、拒绝回执及伤害数字归战斗 |
| 伤害飘字 | combat/api/client/DamageNumber；client/DamageNumbers | 正式回执与训练共用显示记录；暴击标记只在本机传递，按实际字号堆叠与避让，入口及待测项见[实现说明](伤害飘字实现说明.md) |
| 技能 | skills/api/SkillCatalog、SkillParameters、SkillPreviewRules；client/SkillBehaviors、SkillDescriptions、SkillVisualRegistry | 登记稳定ID、学习条件、参数、行为、预览及演出；起手快照不在施放中被重载替换；技能武器加成归SkillDamageRules |
| 职业与任务 | character/api/JobCatalog；application/ProgressService | 定义职业ID、前置职业、等级、击杀/精英/材料条件；不增加单职业布尔字段 |
| 工业设备 | industry/api/DeviceType；platform/IndustrialContent | 组合加工、发能、燃料、流体、物流、收获、选配方和结构能力；同类设备仅登记本模块内容及资源 |
| 工业加工/结构/提示 | industry/platform/IndustrialProcessing、IndustrialGeneration、IndustrialFunctions、IndustrialStructures、IndustrialDeviceInfo | 分别维护加工、发能、功能、结构图样和提示；World只负责拓扑、调度、供能结算及网络事实 |
| 副职业 | professions/application/ProfessionService、ProfessionEvents；api/ProfessionRules | 已提交有效操作才能奖励，保留操作ID去重；未开放职业不能因新增定义自动开放 |
| 容器 | inventory/api/InventoryOperations、PersistentContainer；application/InventoryTransactions | 实现快照/恢复合同；容器操作统一事务；外部模块不直接改库存内部数组 |
| 金币/通货/掉落 | economy/api/CurrencyRules、RewardPorts；application/EconomyService、LootService | 统一资格和金额规则；奖励提交后再发消息；私人拾取与公开掉落拾取分别维护事务 |
| 队伍/副本 | party/application/PartyService；dungeons/application/DungeonService、TargetService、WorldHealthService、DamageMeterService | 跨模块只传玩家/场次及公开数据合同；目标生命适配CombatTarget，不让战斗引用具体副本敌人 |
| 玩家页面 | presentation/api/PlayerPages；api/client/PlayerPageSurface、PlayerPageRenderers | 登记页面和渲染器，内容在所属模块client；bootstrap/PlayerPageAssembly只注入页面所需数据 |
| 主题与自绘面板 | presentation/api/client/ThemeDomain、ThemeContext、ThemedScreen、ThemedContainerScreen、ClientPagePanel | Screen在提取期间作用域读取调色板；自绘I面板通过registerPanel登记，内容/点击归业务模块，菜单壳不复制算法 |
| 客户端消息 | 各模块client/*ClientMessages | 复用CommandRouter登记处理器，ClientSession只装配连接和profile；新增模块消息不增加中央switch |
| 平台注册 | 各模块api/*ContentTypes、platform/*Content | 方块、菜单、附件、实体和状态由所属模块登记；FightMod只绑定事件总线和跨模块端口 |

装备、词条、材料、副本和工业当前仍可共用既有数据包资源文件的不同节，但解析、模型及生命周期各自拥有。改资源内容不必改底层调度器。若普通需求需要越过API或扩大统一算式/网络/事务能力，先解释缺口并按架构保护规则处理。

JSON编解码由模块自己拥有；装备的EquipmentJson保存嵌套词条扩展字段。ApplicationJson仅用于启动装配的组合包，不作为模块反向调用入口。模块可变实例只能在自己的用例或同一事务内改动，规则快照调用者只读。

## 技能权值与伤害分析接口

技能内容使用 `SkillBalanceProfile` 登记权值及参考命中时间，职业内容使用 `SkillBalanceStyle` 登记职业倍率、普攻与固有伤害。`SkillDefinition.damageParameter` 标记自有伤害通道，`SkillParameters` 解析后冻结在起手快照；装备固定附伤不乘全局基数。技能规则接入原整包发布与同步，不扩展受保护底层。装备授予绑定通过 `SkillLearning.canBind` 和角色模块 `SkillProgression` 端口传递当前属性。

战斗模块 `DamageAnalysis` 只持有本地统计轮次与来源凭据，`CombatPrediction` 消费实际伤害回执；训练通过独立入口送入。分析面板通过现有页面登记，角色页负责导航。完整合同及本任务待测试项见[技能权值与伤害分析](技能权值与伤害分析.md)，具体已批准系数见[倍率审阅表](技能权值倍率审阅.md)。


## 具名装备扩展合同

本批新增EquipmentEffects固定参数及授予来源、EquipmentEntitlements契约、SkillCosts消耗/冷却、SkillStartService普通/装备起手、CombatPorts.SkillEffects伤害来源和direct分类、CombatTarget双防/抗性/精英能力、EquipmentBuffs来源与层数。实现和调用归属见[腐化与具名装备实现说明](腐化与具名装备实现说明.md)。没有增加业务模块或修改受保护底层；经济模块新增对affixes公开API的声明，用于批售预览词条。
