# 水晶物流复查

2026年11月2日。范围：移物水晶、供液水晶、机器端口与多级合成；用户补充的实际连接为矿机→涡轮发电机。

## 原因与修复

矿机已经通过底面暴露9格固体产物。原来绑定和运输把所有工业目标固定视作顶部输入；涡轮等发电机的顶部没有固体原料格，燃料槽位于背面，因此连接在目标端失败。现在两条路径共用`CrystalTransfers.portFace`：机器来源选底面，物品目标带FUEL能力时选当前朝向的背面，其他机器目标选顶部；外部容器保留实际点击面。已有当前格式配对在执行时也重新按当前机器朝向解析，不新增存档迁移。

燃料自动输入只接受该设备正式燃料配方的材料，原版漏斗和能力输入共用过滤。涡轮可接煤、木炭、硫化物及对应已登记燃料，仍需1000mB/秒的水；配方、功率和耗能未调整。权杖失败提示明确标出来源输出口或目标输入口，来源选中提示区分物品与液体。

同时发现文档规定的工艺锁定未启用：恢复锻炉的可选工艺、精炼机和反应釜的必选工艺。自动固体投料按每条线的配方原料顺序占格，双液体按工艺顺序占罐。排队切换时，未开工的输入面向下一工艺；当前批次继续使用原快照。已有残料、残液不会被自动销毁或转换。手动固体摆放与完整匹配算法保留。

以上均在工业模块内部完成，没有新增跨模块接口、通用调度、事务或协议修改，保持开工时已有的机器schema4和网络SavedData v2。操作权威说明见[玩家水晶连接](../playerread/工业/README.md#水晶连接)。
