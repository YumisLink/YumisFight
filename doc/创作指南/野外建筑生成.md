# 野外建筑生成规则

新增出生村庄、野外营地、建筑群或独立设施时，复用 `mapgeneration` 应用模块。每张地图由 JSON 蓝图和原版 NBT 结构组成，区域只分道路、其他地面、建筑／设施三类；新增内容不在生成器内增加地图坐标或建筑 ID 分支。

## 入口与资源

| 内容 | 位置／职责 |
|---|---|
| 公开入口 | [MapGeneration.java](../../src/main/java/cn/yumis/fight/modules/mapgeneration/api/MapGeneration.java)：配置登记、出生点生命周期、管理员命令。跨模块只通过本公开面接入。 |
| 配置合同 | [MapBlueprint.java](../../src/main/java/cn/yumis/fight/modules/mapgeneration/api/MapBlueprint.java)：蓝图字段、默认值和校验。 |
| 蓝图 | `src/main/resources/data/<命名空间>/map_blueprint/<路径>.json`，资源 ID 为 `<命名空间>:<路径>`。 |
| 原版结构 | `src/main/resources/data/<命名空间>/structure/<路径>.nbt`，`template` 写资源 ID，不带 `structure/` 前缀或 `.nbt` 后缀。 |
| 初始新手村 | [starter_village.json](../../src/main/resources/data/yumis_dungeon_and_fight/map_blueprint/starter_village.json)，结构在相邻 `structure/map_blueprints/starter_village/`。 |
| 运行配置 | 游戏或服务端目录的 `config/ydcore.toml`，由 NeoForge 原生配置系统创建和读取。 |

规划、换材、地基和放置属于本模块内部实现。新蓝图复用这些能力，不新增通用调度器、网络协议、跨模块内部调用或每次加载重建建筑的循环。当前自动调用负责新世界出生村庄；其他蓝图可以由管理员指定位置生成，不因登记资源就自动在所有区块随机投放。

## 制作并登记一份蓝图

1. 保存、备份最新母版，读取用户当前修改过的方块状态、方块实体和动物。旧制作脚本只用于定位，不能重建旧设计覆盖手工修改。
2. 选定地图锚点，记录外围 `bounds`；每座完整建筑、广场、集市、菜园等各自导出原版 NBT。室内楼层、屋顶、门廊和装饰的相对位置保留在同一结构中。
3. 为每个结构记录最小 X/Z 角、行走面基准、主入口、道路遮挡投影及用途。连廊、双柱灯架等跨设施连接件单独登记归属和接点。
4. 配置道路折线和宽度，接通入口、交点、平整区域及对外出口。用其他地面配置当地地表和植被；需要完整平整的场所归入设施。
5. 登记换材主辅木族、地基、墙段标签、光照目标、动物及战利品。资源 ID 和所有目标方块必须在当前版本真实存在。
6. 将 JSON 和 NBT 放到正式资源目录。新增地图只增加配置和素材；若某项通用能力确实缺失，先在所属模块补配置能力，再让各蓝图复用。

默认新手村保留已认可的 160×160 格主体、224×224 格外围及平面布局。尺寸属于该蓝图，不固定在生成器中；新的建筑群按自身占地填写。

## 三类区域的配置

根对象使用 `version: 1`、`bounds`、`settings`、`roads`、`grounds`、`facilities`。`bounds` 是相对锚点的闭区间 `[minX,minZ,maxX,maxZ]`，控制点、结构和入口须落在范围内。道路、地面和设施的 `id` 在整份蓝图中唯一。

### 道路 `roads`

| 字段 | 写法 |
|---|---|
| `id` | 蓝图内唯一的道路 ID。 |
| `points` | 相对地图锚点的二维 X/Z 折线，至少两个点。折线和栅格交集形成道路网络。 |
| `width` | 道路宽度，单位格；主路、支路、集市通道按用途分配。 |
| `external` | 是否对外出口；浮岛模式会在末端补停靠小平台和护栏。 |

道路不得仅连到建筑包围盒附近，须连到配置入口的实际踏面。`blocked` 表示不能占用的结构列；计算投影时同时考虑踏面下一格的围栏、墙等超过一格高的碰撞，不能只看玩家脚部位置是否为空气。

材料由 `settings.roadBlocks`、`roadSlabs`、`roadStairs` 和 `roadWeights` 逐项配套；坡段分别提供真实半砖、楼梯 ID。默认石头 35%、安山岩 35%、圆石 20%、闪长岩 10%，以小块区域混铺；不能只改整块而让坡段仍用另一套材料。

### 其他地面 `grounds`

| 字段 | 写法 |
|---|---|
| `bounds`、`polygon` | 区域边界；可选多边形也使用相对地图锚点的 X/Z 坐标。 |
| `surface` | `native` 保留自然地面；`biome` 按群系选择表层；也可指定真实方块 ID。 |
| `clearVegetation` | 是否清理该区域已有的自然树木和可替换植被。开启前确认范围。 |
| `plants` | 植被落点，每项写 `x`、`z`、`block`、`tall`；由生成器按当地基底检查能否存活。 |
| `island` | 可关联一个设施 ID；浮岛模式把该片地面并入对应岛体。关联设施须存在且启用成岛。 |

自然草地不复制成一整块固定高度土台。沙漠使用当地沙地，海面保留原海水，不把自然地面区铺成土岛。陆生花草避开水面、道路、入口和空置广场；两格高植物须成对放置。需要固定种植基底、蓄水或平整作业面的菜园和池塘改用设施登记。

### 建筑／设施 `facilities`

| 字段 | 写法 |
|---|---|
| `template` | 原版结构资源 ID。 |
| `position` | NBT 最小角相对地图锚点的 `[x,z]`。 |
| `referenceY` | 行走面相对 NBT 底部的高度。整块地板通常在 `referenceY - 1`；不是屋顶或最低装饰物的高度。 |
| `entrance` | 主入口相对地图锚点的 `[x,z]`，不是相对 NBT 的坐标。 |
| `anchor` | `road` 按入口道路整体定高；`surface` 适合随当地地表落地的独立树木、装饰。 |
| `flatten` | 是否将入口平段纳入统一高度求解；完整建筑和场所通常开启。 |
| `platform` | 是否作为有完整基准面的设施处理；零散装饰通常关闭。 |
| `parent` | 需要同高的主设施 ID。父项须存在且无循环，连接件与入口一起规划；当前环境跳过父项时，其依赖也须正确配置。 |
| `blocked` | 相对 NBT 最小 X/Z 角的二维遮挡投影。须排除真实通路、门洞和可穿行处。 |
| `foundation` | 地基方式，见下节；默认 `platform`。 |
| `island` | 浮岛模式是否为其生成独立岛体。 |
| `skipInOcean` | 是否在海上模式省略，如仅适合陆地的独立景观树。 |
| `tags` | 墙段与附属墙廊使用 `wall`；仍属于设施，不增加第四类区域。门楼、独立哨塔不标记为墙段。 |
| `keepClear` | 空置广场使用；素材仅保留地面，补灯、植被和自动栏杆避开有效占地。 |
| `lightTarget` | 该设施的夜间方块光照目标，0 表示不自动补灯。 |
| `loot` | 每项包含结构内三维 `pos` 和现有战利品表 `table`；目标必须是可用容器。 |

`kind` 可记录设施用途，生成行为仍由上述配置决定，不能据此新增中央建筑分支。完整建筑只整体升降，内部层高、屋顶与台阶的相对形状不随地面扭曲；源母版北部的局部抬高也不能写成统一规则。

## 高度、道路与地基

落块前读取完整自然地形，组织道路折线、交点、设施入口和同高区域，以半格高度单位统一求解。普通选点从脚下的原版自然地表起算，低于浮岛阈值的飞行选点仍投影回地面。

默认 `maxRise=1`，相邻道路每格升降不超过一格。每个入口沿道路方向前后各 3 格，共 7 格全路宽保持平整；设施跟随入口基准整体放置。平台外预留末端 1～2 格楼梯或半砖，接入原坡段；上行楼梯高侧朝平台，下行按实际坡向连接。结构模板落下后再校正末端，不能把最后一级楼梯抹成整块而留下需要跳跃的立坎。

原版入口地面及架空时抬高一格作为地形适配的优先目标，不是不可下调的高度下限。先按世界边界、出生锚点和道路坡度求出可达高度，再将该目标限制在可达范围内；高坡由削坡、挡土或支撑收口，不能因为入口原地面较高就让整张蓝图规划失败。

| `foundation` | 适用方式 |
|---|---|
| `platform` | 普通房屋和工作设施。按平台占地处理，必要时补完整基面、落地长柱、石柱脚与横撑。 |
| `sparse_stone` | 广场等开敞铺装。沿真实落地轮廓局部补最多两层短石基，保留素材缺口和周围地形，不补成长方形木地板。 |
| `terrain_retaining` | 大树屋等贴地设施。沿实际根系、地板和门廊补落地石质挡土面，外围以两格错台衔接；高差大时可以形成较高石墙，不能按树冠包围盒补木平台或木柱。 |

后两种地基须启用 `platform`，从 `referenceY` 以下的实体承托方块提取轮廓。只清理实际占地内与结构、通行冲突的地形；外围挡土避开道路和其他设施。地基参与规划碰撞检查，普通森林用石头、圆石、安山岩和少量苔石；沙漠、恶地换成协调的砂岩、红砂岩等环境材料。
