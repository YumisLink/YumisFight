# 模块地图

本页回答两个问题：**哪个模块在哪里**、**制作什么需要动哪些模块**。只管位置、归属和配套文件；任务到具体类名的入口查 [项目索引](README.md)，参数与复用方法查 [创作指南](创作指南/README.md)，权威划分与测试要求以 [AGENTS](../AGENTS.md) 为准。路径未注明时均相对仓库根。

## 1. 布局约定与装配

| 层 | 位置 |
|---|---|
| 主源码（服务器权威 + 共用规则） | `src/main/java/cn/yumis/fight/` |
| 客户端源码（本机判定、界面、演出） | `src/client/java/cn/yumis/fight/` |
| 业务模块 | 两侧 `modules/<模块名>/` 同名对应，共 18 个 |
| 规则与数据包 | `src/main/resources/data/yumis_dungeon_and_fight/` |
| 资源包（模型、贴图、语言、着色器） | `src/main/resources/assets/yumis_dungeon_and_fight/` |

模块内目录分工（跨模块只允许消费 `api`）：

| 子目录 | 放什么 |
|---|---|
| `api/` | 公开接口与定义，其他模块只从这里调用 |
| `api/client/` | 客户端侧公开合同（部分模块在主源码侧声明） |
| `application/` | 服务器侧服务、事实保存与回执，仅本模块内部使用 |
| `platform/` | 方块、物品、实体、菜单等平台注册挂载 |
| `content/` | 副本与地图内容布局（dungeons） |
| `client/` | 客户端实现，位于客户端源码的同名模块 |

| 查什么 | 在哪里 |
|---|---|
| 模块登记与依赖关系 | 主源码 `bootstrap/ApplicationModules.java`，新增模块或改依赖动这里 |
| 服务器装配与规则装载 | 主源码 `bootstrap/ServerApplication.java`、`ApplicationRules.java` |
| 客户端装配 | 客户端 `bootstrap/ClientBootstrap.java`、`ClientSession.java` |
| 底层边界（受保护） | `architecture/`、`foundation/Journal.java`、`network/Network.java`，清单 [protected-files.json](../architecture/protected-files.json) |
| 模块边界检查 | `gradle/architecture.gradle`，属于受保护文件 |

| `presentation` | 页面、主题、富文本、粒子、通用绘制 | mining |

## 3. 制作什么 → 用哪些模块

「主责」是内容登记或修改的归属模块；「配合」按任务实际涉及选用。每个模块内具体入口类查 [项目索引](README.md)，本表给的是模块集合与配套文件。

## 4. 逐模块明细

以下路径相对所属模块目录（`src/main/java/cn/yumis/fight/modules/<模块>/`）书写；跨模块引用与客户端路径写成完整相对路径，客户端路径省略 `src/client/java/cn/yumis/fight/modules/` 前缀。

### 属性与词条

**`attributes` — 属性与统一算式**：主源码仅 `api/`，无 application／platform。公开面：`Stats`／`Stat`（属性聚合与枚举）、`AttributeSources`（来源汇总）、`AttributeNumbers`／`AttributeServices`（数值与服务）、`ExtraDamage`、`ParameterModifier`、`AttributeNames`（消费 `rules/catalog.json` 的 `statNames` 显示名）。客户端 `attributes/api/client/AttributeLabels.java`。统一算式在 `architecture/AttributeMath.java`（受保护）。测试 `AttributeSourcesTest`。

**`affixes` — 词条**：主源码仅 `api/`。公开面：`AffixDefinitions`／`AffixDefinition`（定义登记）、`AffixGeneration`（抽取）、`AffixEffects`／`MagicEffects`（效果）、`AffixResolver`（解析）、`AffixLevelCurves`（可变宽成长区间）、`AffixJson`／`AffixText`（编解码与文字）、`AttackSpeedRoll`。客户端 `affixes/api/client/AffixFavorites.java`（收藏）。配套：区间与资格在 `equipment/api/EquipmentAffix*`。测试 `AffixCurrencyTest`、`AffixRangesTest`、`AffixRevisionTest`。

### 角色与成长

**`character` — 角色与存档**：`api/` 公开面：`JobCatalog`（职业目录）、`JobTransitions`（转职）、`CareerProfiles`／`ProfileConditions`（档案与资格）、`CharacterChanges`／`CharacterActions`／`CharacterAttributes`／`CharacterItems`（改动合同）、`CharacterRules`／`Progress`／`SkillProgression`／`TalentProgression`（成长进度）、`CharacterPersistence`（存档端口）。`application/CharacterStore.java`（编解码）、`ProgressService.java`；`platform/CharacterContent.java`。客户端 `character/api/client/CareerControls.java`、`CareerProfilesClient.java`，`character/client/CharacterClient.java`、`CharacterPage.java`。测试 `ProgressMovementTest`。

**`talents` — 天赋**：主源码仅 `api/`：`TalentCatalog`、`TalentAttributes`、`TalentChanges`、`TalentConditions`、`TalentEffects`、`TalentLedger`。客户端 `talents/client/TalentCombat.java`（战斗内应用）。配套 `rules/talents.json`。

### 战斗与技能

**`combat` — 战斗与生命**：`api/` 公开面按职责分组——生命：`Life`、`LifeRules`、`WorldVitalEntity`、`RuntimeCheckpoint`；规则：`CombatRules`、`CombatSettings`、`CombatTiming`、`LevelAdvantage`、`NativeEffects`；回执：`Receipt`、`Runtime`、`CombatSession`、`CombatPorts`、`CombatContentTypes`；目标命中：`CombatTarget`、`ManagedEntities`、`ProjectileSpawn`、`BasicAttackProfile`；装备接入：`EquipmentBuffs`、`EquipmentDamage`、`EquipmentHitEffects`；元素异常：`ElementAccumulation`、`CombatEffect`。`application/CombatApplication.java`（服务器回执）、`NativeHits.java`、`StunControl.java`、`VanillaAttackClock.java`。客户端 `combat/api/client/`（`CombatPrediction`、`DamageAnalysis`、`DamageNumber`）与 `combat/client/`（`DamageNumbers`、`EnemyHealthBars`、`ElementAccumulationHud`、`EquipmentBuffHud`、`TargetHudFocus`、`DamageAnalysisPanel`）。原版战斗接管在主源码 `mixin/Native*`。测试 `DamageMeterTest`、`CombatEquipmentRevisionTest`，实机探针 `verification/CombatVerification.java`。
